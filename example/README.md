# Пример сайта

Из checkout:

```sh
npm ci
npm run dev:example
```

Откройте `http://127.0.0.1:3000/example/index.html` (script tag) или
`http://127.0.0.1:3000/example/npm.html` (npm import через Vite).
В checkout npm import разрешается на собранный `dist/index.js`, не на `src`.
Заполните форму API/шлюза, Application UUID и public VAPID key. Значения не
сохраняются примером и не отправляются до кнопки «Подключить PushPilot».

1. Подключите SDK. Разрешение пока не запрашивается.
2. Нажмите «Разрешить уведомления». `denied` требует изменения настройки сайта;
   `default` позволяет повторить запрос.
3. Нажмите «Подписаться». Успех означает регистрацию браузерной подписки в API.
4. Нажмите «Отписаться». При API-ошибке подписка остаётся, операция повторяется кнопкой.
5. «Показать локальное уведомление» показывает уведомление через worker. Нажмите
   на него в системном центре уведомлений: сайт открывается/фокусируется, открытая
   страница получает событие. Холодное открытие обрабатывайте через URL.

Для отдельного проекта установите пакет, скопируйте эти HTML/JS файлы в свой
сайт и выполните из корня проекта:

```sh
node node_modules/@pushplatform/web-sdk/scripts/copy-assets.mjs public
```

Это кладёт два собранных JS в `public/vendor`. Поместите `service-worker.js` рядом
с `vendor/` и страницей для script-примера. Для npm-примера используйте bundler
(например, Vite): bare import `@pushplatform/web-sdk` разрешается из node_modules.
Путь `./service-worker.js` и scope `./` относятся к директории страницы.
Не открывайте HTML через `file://`; используйте HTTPS или localhost.

На публичном сайте нужен серверный шлюз либо будущий публичный API-контракт;
секретный ключ PushPilot не публикуйте. [Подробнее](../README.md).
Локальное уведомление и автоматические fixture-тесты не проверяют доставку через
внешний push-сервис.
